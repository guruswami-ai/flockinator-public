# Canary golden vectors 001

`canary-golden-vectors-001.csv`: 300 rows (seeds 80-82, 100 ticks
each, zero injected loss) of the canary broadcast input stream
with the contract-expected journal output per tick:
`tick,seed,signal_q,obstacle,pkt_loss,input_hash,decision`.

Purpose: the ESP32 firmware port feeds these exact inputs to its
decision code and compares its journal row by row - hash and
decision must match all 300 rows before any radio or SD work is
trusted. Generated by `kulira_core.twin.tick_inputs` (the same
stream `run_twin` consumes, by construction), contract
`docs/experiments/canary-contract-v1.md` v1.1. Missing-input
rows are not in this file; they are covered by the comparator
unit tests (`missing_hash` semantics).
